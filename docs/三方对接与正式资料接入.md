# Three-party integration and formal material onboarding

This project splits the frozen official materials into four knowledge groups, then retrieves evidence and generates answers with citations. A delivers regulations and standard questions; B provides chunking, BGE-M3 and Chroma retrieval; C connects materials, retrieval, Q&A, sessions, experiments and pages. Pages and evaluation must use the same Q&A chain.

2026-11-20 has merged A's formal delivery (main 66dbada): 5 EUR-Lex original published English regulations, 121 main articles, 24 answerable + 6 refusal. `config/experiment.formal-a.json` is the new formal configuration that passed validation; the original default `config/experiment.json` is still used for development samples. Formal Q&A, experiments and legacy synthetic evidence are recorded separately. See the latest `docs/handoffs/` for actual stage status and `docs/worklogs/` for operations.

## 1. Existing environment and installation

Team baseline Python 3.13.11, using project `.venv`. This computer's environment and about 2.3 GB of models are already prepared; no rebuild or re-download is needed to continue work.

On a new machine, install the full runtime dependencies `requirements.txt` in the DERag directory; install `requirements-dev.txt` when automatic checks need to run. B and C's original separate lock files are retained; `requirements-c-dev.txt` is only for lightweight C development without B.

```powershell
# Create only on a new machine with no environment yet; do not overwrite an existing .venv
py -3.13 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m pip check
```

Windows paths need room for Chroma's version directories, UUIDs and native filenames. The program rejects a final Chroma directory longer than 200 characters; on encountering `INDEX_PATH_TOO_LONG`, first stop services using that data directory, choose a shorter `DERAG_DATA_DIR`, copy the full frozen materials byte-for-byte, re-validate and rebuild the index, and keep the original materials. Do not disable path protection or change system settings to force it through. Tests use short, separate Temp directories.

## 2. A's frozen input and C's read-only adaptation

A has delivered the following frozen materials. The actual corpus package is at `data/formal_corpus`, the question set at `data/eval`, and the full acceptance structure at `data/processed`. C only validates and integrates; it does not change answers to accommodate retrieval results.

| Location | Required contents |
| --- | --- |
| `data/raw/` | Original snapshots of 5–8 formal official materials, preserving original bytes. |
| `data/formal_corpus/processed/` | Rich Documents exported by A: body text, source, date, SHA, main article location, chapter/section/block, etc. |
| `data/processed/*.json`, `*.txt` | A's full accepted structure and full text; including annexes etc. beyond main articles, for annex evidence validation. |
| `data/formal_corpus/manifest.json` | schema_version=1.0, parser_version, corpus_version; per-document paths with raw_sha256, processed_sha256, text_sha256, structure_sha256. Versions computed per development documentation spec. |
| `data/eval/gold.jsonl` | Exactly 24 answerable questions and 6 questions that should be refused; answerable ones include reference answers, key points, verbatim evidence and article/character positions; refusal ones state why the frozen corpus is insufficient. |
| `data/eval/manifest.json` | schema_version=1.0, matching corpus_version, gold_version, 24/6 count. gold_version is the SHA-256 of the final gold.jsonl raw bytes. |

JSON/JSONL must be UTF-8 without BOM, LF; gold.jsonl ends with a newline. manifest uses portable relative paths (e.g. `data/raw/a.html`), no personal drive letters, backslashes or `..`. Formal questions should be frozen before A views the four groups' retrieval/generation results. For this round's formal topics, language and original published version scope, A's delivery notes prevail; this frozen-corpus experiment does not claim to use the latest consolidated amended regulations.

On receipt, first record the delivery directory or repository branch, commit, file list, both versions and A's independent validation results. If a new delivery has the same filename as an existing file, compare hashes first and do not overwrite directly; if they differ, A revises and re-freezes.

## 3. Configure the large model connection

Project `.env.example` describes the endpoint, model and Key variables. The real Key goes in a local, ignored `.env` or an explicitly specified private env file; do not write it into JSON config, reports, command-line arguments or Git. For the specific location of this computer's school connection, see the outer workspace document "学校LLM_API对接文档.md"; no need to check other course folders.

`DERAG_ENV_FILE` specifies the private file in the **process environment**; it is not an instruction for dotenv to recursively find other files. `DERAG_CONFIG` selects the experiment JSON; data and model paths are resolved relative to DERag. Program startup does not automatically download models, build indexes or make generation requests.

Field priority: explicit parameters/override > process environment fields > specified or default dotenv fields > JSON. Env file selection is explicit `env_file` > process `DERAG_ENV_FILE` > project `.env`; config file selection is explicit `--config` > `DERAG_CONFIG` > default JSON. Generation transport explicitly specifies `curl` or `httpx`; it does not automatically switch transport.

The school API's existing successful local validation used `curl`. You can write `LLM_TRANSPORT=curl` in `.env`, or set `$env:LLM_TRANSPORT='curl'` in the current PowerShell; curl uses TLS verification. The default JSON remains httpx; do not treat Windows curl success as Linux/Docker/HTTPX validation.

## 4. Order of using formal input

The following commands run from DERag and explicitly select the formal configuration; if files do not exist they fail explicitly and do not automatically fall back to samples.

First generate a brand-new formal configuration; if one exists, choose a new filename and do not overwrite the old experiment configuration.

```powershell
.venv/Scripts/python.exe -m scripts.prepare_config --data-dir data/formal_corpus --output config/experiment.formal-NEW.json --transport curl
$env:DERAG_CONFIG='config/experiment.formal-a.json'
$env:DERAG_ENV_FILE='../.private/school-llm.env'
.venv/Scripts/python.exe -m scripts.validate_data --config config/experiment.formal-a.json
```

Run prepare_config only when the new configuration does not exist; formal-a has already been generated on this machine, do not regenerate it to restore context. The tool recognizes A's formal_corpus manifest and automatically uses the sibling eval and processed; other layouts can explicitly pass `--gold-dir`, `--structure-dir`. It validates 5–8 documents, 24+6, hashes and evidence, then writes the new configuration without modifying A or copying the Key. `input_adapter=eurlex-a-v1` only maps quote/should_refuse fields in memory; it retains refusal reference text and original annex structure_id. Full structure is first compared against A's exported record SHA, then annex ranges are validated. B receives the untrimmed original dictionary; source_digest is unchanged. Use `validate_data --config ... --corpus-only` only to check corpus availability; success does not mean evaluation is ready. A's original entries `validate_data --scope corpus` / `--scope eval` are retained; empty arguments error per A's required rules, and C's default entry switches to `python -m scripts.validate_integration`.

Only a new machine missing models runs the download; existing models are verified with the manifest and not re-downloaded.

```powershell
.venv/Scripts/python.exe -m scripts.fetch_embedding
```

BGE-M3 is pinned to revision `5617a9f61b028005a4858fdac845db406aefb181`. `derag-model-manifest.json` inside the model stores file SHAs; weights do not go into ordinary Git. Then stop other services in the same directory and build the four index groups with production B code:

```powershell
.venv/Scripts/python.exe -m scripts.build_indexes
.venv/Scripts/python.exe -m scripts.preflight --output artifacts/c/formal-preflight-01.json
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

preflight does not download, build indexes, encode or call the generation API; it verifies pinned dependencies, A data and question set, model files, four indexes and generation config. `generation.connectivity_verified=false` means it did not test a paid connection; a configured Key does not guarantee future balance/validity. `formal_ready=true` only in formal mode and when everything matches. When QA is ready but the question set is missing, it may show `ready_for_qa=true`, `ready_for_evaluation=false`, and the whole preflight still returns a non-zero exit code.

Run only one service process per data directory, without `--reload` or multiple workers. Pages are `/`, `/documents`, `/compare`, `/evaluation`; first check health status, material version and sources, then use one question to verify retrieval→generation→citation→background save. Stop and restart; history should be readable as-is without regeneration.

Formal acceptance must verify official sources and body text; do not substitute local synthetic integration testing for this step. Only after M5 passes do you enter M6's 30×4 formal experiment and actual manual scoring; see "评估使用说明.md" for details. synthetic reviewer or mock scoring in automated tests cannot serve as formal manual scoring.

## 5. Index rebuild, rest and recovery

The four groups are fixed as f400, s400, f800, s800, top_k=5. The same version uses the same model, cosine metric and HNSW parameters. Persistence adaptation strategy `singleton-checkpoint-v1` has entered the index_version materials; early indexes without this strategy should be rebuilt in a new version directory via the normal index-build entry. Old indexes, historical citations and experiment records are retained, not directly deleted or overwritten.

SQLite is at `sqlite/derag.sqlite3` in the current data directory; full citations are snapshots at save time. Evaluation resumes an existing run_id; do not click "start new experiment" as a substitute for recovery; unfinished tasks after restart are explicitly marked interrupted. After actual long-running tasks finish or are confirmed interrupted, save the day's operation log, stage handover and branch checkpoint, recording what passed, what is pending, and real request counts/tokens. Do not write unrun validations as passed.

M7 will separately do clean-environment, Linux CPU, Docker and delivery-package validation. The current old `DE.tar` is a frontend preview and cannot serve as an accepted image of the new three-party backend.
