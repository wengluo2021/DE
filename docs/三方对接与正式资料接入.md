# 三方对接与正式资料接入

本项目把冻结的官方资料切成四组知识块，再检索证据、生成带引用的回答。A 交付法规和标准题；B 提供分块、BGE-M3 与 Chroma 检索；C 把资料、检索、问答、会话、实验和页面连起来。页面和评估必须使用同一条问答链路。

当前默认 `config/experiment.json` 是开发配置，语料版本为 `fixture-en-v2`，没有正式 gold。仓库中的 B 样例、自动测试题和本地联调结果都是合成资料。A 的正式输入尚未交付到已检查的位置；不能据此开始正式成绩计算。实际阶段状态见最新 `docs/handoffs/`，每次操作见 `docs/worklogs/`。

## 1. 已有环境与安装

团队基线 Python 3.13.11，使用项目 `.venv`。这台电脑的环境和约 2.3 GB 模型已经准备好，继续工作无需重建或重复下载。

新机器在 DERag 目录安装完整运行依赖 `requirements.txt`；需要运行自动检查时安装 `requirements-dev.txt`。B、C 原来的独立锁文件保留，`requirements-c-dev.txt` 只用于不含 B 的轻量 C 开发。

```powershell
# 仅新机器且尚无环境时创建；已有 .venv 不要覆盖
py -3.13 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m pip check
```

Windows 路径需要留出空间给 Chroma 的版本目录、UUID 与原生文件名。程序会拒绝超过 200 字符的最终 Chroma 目录；遇到 `INDEX_PATH_TOO_LONG` 时先停止使用该数据目录的服务，选较短的 `DERAG_DATA_DIR`，把完整冻结资料按原字节复制过去并重新校验、建库，保留原资料。不要关闭路径保护或修改系统设置来硬跑。测试使用短的独立 Temp 目录。

## 2. A 需要交付什么

由 A 提供以下完整冻结文件及来源说明；C 只校验和接入，不改答案迁就检索结果。

| 位置 | 必须包含的内容 |
| --- | --- |
| `data/raw/` | 5–8 份正式官方资料的原始快照，保持原始字节。 |
| `data/processed/` | 每份资料一个 Document JSON：正文、来源、发布/生效日期、原始 SHA、条文 ID 和字符起止位置等。 |
| `data/manifest.json` | schema_version=1.0、parser_version、corpus_version；逐文档路径与 raw_sha256、processed_sha256、text_sha256、structure_sha256。版本按开发文档规范计算。 |
| `data/eval/gold.jsonl` | 恰好 24 道可答题和 6 道应拒答题；可答题含参考答案、要点、逐字证据及条文/字符位置；拒答题写明冻结语料为什么不足。 |
| `data/eval/manifest.json` | schema_version=1.0、匹配的 corpus_version、gold_version、24/6 数量。gold_version 为最终 gold.jsonl 原始字节 SHA-256。 |

JSON/JSONL 必须 UTF-8 无 BOM、LF；gold.jsonl 末尾有换行。manifest 使用可移植相对路径（如 `data/raw/a.html`），不含个人盘符、反斜杠或 `..`。正式题应在 A 查看四组检索/生成结果之前冻结。主题、语言、资料版本由正式团队交付决定，不能拿 B 的英文合成样例推断主题已改变。

接收时先记录交付目录或仓库分支、提交、文件清单、两个版本和 A 的独立验证结果。新交付若与既有文件同名，先比较哈希，不直接覆盖；有差异由 A 修订并重新冻结。

## 3. 配置大模型连接

项目 `.env.example` 说明端点、模型和 Key 变量。真实 Key 放在本地、被忽略的 `.env` 或明确指定的私密 env 文件；不写入 JSON 配置、报告、命令行参数或 Git。当前电脑学校连接的具体位置见工作区外层《学校LLM_API对接文档.md》，无需再查其他课程文件夹。

`DERAG_ENV_FILE` 在**进程环境**中指定私密文件；它不是 dotenv 内递归寻找其他文件的指令。`DERAG_CONFIG` 选择实验 JSON；数据、模型路径均相对 DERag 解析。程序启动不会自动下载模型、建库或发生成请求。

字段优先级：显式参数/override > 进程环境字段 > 指定或默认 dotenv 字段 > JSON。env 文件的选择是显式 `env_file` > 进程 `DERAG_ENV_FILE` > 项目 `.env`；配置文件的选择是显式 `--config` > `DERAG_CONFIG` > 默认 JSON。生成 transport 明确指定 `curl` 或 `httpx`，不会自动换传输方式。

学校 API 的本机既有成功验证使用 `curl`。可在 `.env` 写 `LLM_TRANSPORT=curl`，或在当前 PowerShell 设置 `$env:LLM_TRANSPORT='curl'`；curl 使用 TLS 校验。默认 JSON 仍为 httpx，不把 Windows curl 成功视为 Linux/Docker/HTTPX 验证。

## 4. 正式输入到位后的顺序

下列命令从 DERag 运行。只有收到 A 的正式冻结文件后执行；文件不存在会明确失败，不自动换用样例。

先生成一个全新的正式配置；已存在时选新的文件名，不覆盖旧实验配置。

```powershell
.venv/Scripts/python.exe -m scripts.prepare_config --data-dir data --output config/experiment.formal.json --transport curl
$env:DERAG_CONFIG='config/experiment.formal.json'
.venv/Scripts/python.exe -m scripts.validate_data
```

prepare_config 会读取两个 manifest，验证正式 5–8 份文档、24+6 题、哈希和证据位置，再写配置；不修改 A 的输入或复制 Key。只想检查语料而尚未有题集时可用 validate_data 的 `--corpus-only`，但其成功不代表评估就绪。

模型缺失的新机器才执行下载；已有模型用 manifest 校验，不重复下载。

```powershell
.venv/Scripts/python.exe -m scripts.fetch_embedding
```

BGE-M3 固定 revision 为 `5617a9f61b028005a4858fdac845db406aefb181`。模型内 `derag-model-manifest.json` 保存文件 SHA；权重不进普通 Git。然后停止同目录的其他服务，用生产 B 代码建立四组索引：

```powershell
.venv/Scripts/python.exe -m scripts.build_indexes
.venv/Scripts/python.exe -m scripts.preflight --output artifacts/c/formal-preflight-01.json
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

preflight 不下载、不建库、不编码、不调用生成 API；它核验固定依赖、A 数据和题集、模型文件、四索引和生成配置。`generation.connectivity_verified=false` 表示它没有付费测试连接；Key 已配置也不保证未来余额/有效期。只有正式模式且全部匹配时 `formal_ready=true`。QA 已就绪但题集缺失时可显示 `ready_for_qa=true`、`ready_for_evaluation=false`，整个 preflight 仍返回非零退出码。

同数据目录只运行一个服务进程，不加 `--reload` 或多个 workers。页面为 `/`、`/documents`、`/compare`、`/evaluation`；先看健康状态、资料版本和来源，再用一题验证检索→生成→引用→后台保存。停止后重新启动，历史应原样可读，不重新生成。

正式验收须验证官方来源与正文，不把本地合成联调替代这一步。M5 通过后才进入 M6 的 30×4 正式实验与实际人工评分，具体操作见《评估使用说明.md》。自动测试中的 synthetic reviewer 或 mock 评分不能作为正式人工评分。

## 5. 索引重建、休息与恢复

四组固定为 f400、s400、f800、s800，top_k=5。同一版本使用同一模型、余弦度量与 HNSW 参数。持久化适配策略 `singleton-checkpoint-v1` 已进入 index_version 材料；早期不含此策略的索引应通过正常建库入口在新版本目录重建。旧库、历史引用和实验记录保留，不直接删除或覆盖。

SQLite 位于当前数据目录的 `sqlite/derag.sqlite3`；完整引用是保存时的快照。评估续读已有 run_id，不点击“开始新实验”替代恢复；重启后未完成任务会明确标记中断。实际耗时任务结束或确认中断后，再保存当日操作日志、阶段交接和分支检查点，记录哪些通过、哪些待办、真实请求次数/token。不要把未跑的验证写成通过。

M7 将另做干净环境、Linux CPU、Docker 和交付包验证。目前旧 `DE.tar` 属于前端预览，不能作为新版三方后台已验收的镜像。
