## 换机器

1. 将源码ZIP解压到一个新的目录。在尚未加入运行数据前，运行`python -B -S scripts/verify_delivery.py .`核对清单；该命令只用标准库。
2. 校验结果ZIP后，解压到同一个新源码根，得到artifacts证据及sqlite-backup。SQLite备份只用于新的数据库目录/新Docker卷；恢复时确认目标不存在，不覆盖当前电脑已有评分。
3. 权重TAR在新源码根解压后得到models/embedding。新机器要生成新问答时才按既有Docker指南重建本机原生索引；不跨平台复制个人venv或Windows原生Chroma来冒充Linux重建。
4. `docker load --input DE.tar`加载离线镜像。按最终包README里的tag和挂载命令，在空Key模式先读取备份中的已有结果。查看现有成绩无需学校连通性探测或重跑120题。
5. 需要新生成时才配置自己的私密env，并遵守冻结配置。原Key没有进入包。容器只使用一个worker，不加reload。

源码目录中的`DELIVERY-MANIFEST.json`用于核对刚解压的源码/数据；加入模型、artifacts、数据库或缓存后，目录已成为运行工作区，不能再当成原始解包快照核验。先验包、再添加运行文件。
