## Moving to another machine

1. Extract the source ZIP into a new directory. Before adding runtime data, run the `python -B -S scripts/verify_delivery.py .` checklist; this command uses only the standard library.
2. After verifying the results ZIP, extract it into the same new source root to obtain the artifacts evidence and sqlite-backup. The SQLite backup is only for a new database directory/new Docker volume; when restoring, confirm the target does not exist and do not overwrite existing scores on the current computer.
3. Extract the weights TAR in the new source root to get models/embedding. Only when the new machine needs to generate new Q&A should you rebuild the local native index per the existing Docker guide; do not copy a personal venv or Windows-native Chroma across platforms to pass it off as a Linux rebuild.
4. `docker load --input DE.tar` load the offline image. Follow the tag and mount commands in the final package README, and in empty-Key mode first read the existing results from the backup. Viewing existing results requires no school connectivity probe and no rerun of the 120 questions.
5. Only when new generation is needed, configure your own private env and follow the frozen configuration. The original Key did not enter the package. The container uses only one worker, without reload.

The `DELIVERY-MANIFEST.json` in the source directory is for verifying the just-extracted source/data; after adding models, artifacts, database, or cache, the directory has become a runtime workspace and can no longer be verified as a pristine unpacked snapshot. Verify the package first, then add runtime files.
