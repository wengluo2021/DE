**Entry points that M1 must continue to use.**

- `Claim.text` does not allow embedded `[number]` references; numbers may only come from citation_numbers, and `render_answer(claims)` then generates the display text.
- `hit.validate_source(document)`: validates the frozen body span, title, URL, actually covered provisions, and article numbers; it must be called explicitly before handing off to the model.
- `result.validate_snapshot(retrieval)`: verifies that the Answer matches the original SearchResult version, and that all hits from this round are preserved as-is, including evidence not referenced by claims; it must be called explicitly.
- `ModelOutput` accepts only status/claims, not another free-text answer; insufficient allows only empty claims, and the final refusal uses INSUFFICIENT_ANSWER.
- `load_settings(...)` does not import B's heavy modules, does not access the network, does not search for other course keys, and does not modify os.environ.
- Configuration priority is explicit overrides/api_key → process environ → explicit/default .env → JSON; `api_key=''` can be cleared, and a blank key is treated as unconfigured.
- `Settings.retrieval_config()` returns a new dictionary for use by the existing B. `public_snapshot()` contains no keys; `experiment_fingerprint()` contains no machine paths or credential status, and includes the prompt content hash.
- Official mode requires the corpus/question set to have the SHA-256 shape; the actual manifest and version authenticity are still verified by subsequent A/B loading and validation, and passing syntax must not be treated as the existence of official data.
