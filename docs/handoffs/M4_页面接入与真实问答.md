**What the pages can do now.**

| Page | Backend behavior |
| --- | --- |
| Q&A / | POST /api/ask, server-side session list and history; success/refusal/failure kept separate; no longer generates browser demo answers. |
| Documents /documents | A frozen material summaries/details/sources; builds B's four index groups, reads persistent task progress; no longer imports from the browser and rewrites official body text. |
| Chunk comparison /compare | Reads actual ingested chunks; calls B's compare for the same question, both sides share a version and return top-5, character counts, and elapsed time; no longer reimplements chunking in the browser. |
| Evaluation /evaluation | Reads existing runs, submits 30×4 backend experiments, refreshes for later viewing, four-group metrics/pending review/failures, per-question-type scores and per-claim reasons, JSON/CSV download. |

Core changes are in app/static/app.js, index.html, styles.css. The original layout is retained; app.main version 0.4.0, health.frontend_mode=api. B's chunking/retrieval implementation was not changed, and no separate production entry point was created. The test adapter is in tests/support/frontend_app.py and is not imported by the production entry point.

Citation buttons are located by ask_id+n, not by bare [1] within a session. Details save the current turn's title, article number, URL, range, full text, and version; opening the frozen original uses Array.from to slice by Unicode code point, aligning with Python's [start,end). Text is uniformly escaped, and source links allow only http/https.

The modal has keyboard Tab trapping, Escape to close, focus return, and background inert; the navigation/session bar collapsed on narrow screens no longer enters keyboard and AX. Scoring drafts are kept only in this page's memory; after viewing the original you can "return to this question's scoring"; only pressing save writes to the backend, so save scores before refreshing the page.

The frontend keeps only the in-progress task_id/run_id/kind in localStorage to allow resuming after refresh; answers, evidence, and scores are authoritative in SQLite, and it does not read the old preview's browser sessions or demo materials. Network failures do not automatically resend POST; the prompt advises checking the server-side record first.
