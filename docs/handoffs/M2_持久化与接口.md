**External interfaces and states.**

- POST `/api/ask`: input AskRequest, success returns the original AskResult; saves all evidence for this round, and retains the QA record even on failure.
- GET `/api/conversations`: items list; GET `/api/conversations/{id}`: question, valid result/error, and evidence snapshot. Raw provider candidates/internal trace are not echoed in the normal history interface, but are still retained internally in the database for evaluation.
- GET `/api/tasks/{id}`: queued/running/completed/failed, progress, result/error, and result_id.
- GET `/api/health`: service liveness and component readiness are separate, publicly exposes redacted config and experiment fingerprint; does not call the model to check health. A configured model does not mean connectivity has been verified.
- The original B document/build/retrieval/comparison routes are registered on the formal entry point; when there is no formal material, returns an explicit 409, does not automatically enable fixture or demo answers.
- Errors unified as code/message; 422 input, 404 not found, 409 version/not configured, 502/503 generation/upstream failure; no unverified answer is shown as success.

The default database is `data/sqlite/derag.sqlite3`, resolved by DERAG_DATA_DIR; generated files and locks are Git-ignored. No need to copy the database from the developer machine as formal data.

**Shutdown and recovery semantics.**

Each QA first saves running and the request/actual config, saves progress after retrieval validation and on each generation attempt, and completes result and evidence in a transaction. After a hard interruption, the next service holding the database lease marks leftover running QA and queued/running tasks as PROCESS_INTERRUPTED, retaining existing snapshots, responses, and progress; does not secretly re-request the model.

Task Python functions are not serialized or pickled; after restart old tasks are marked failed and a new task must be created to re-run. Normal shutdown waits for its own worker to finish before releasing the lease. Production uses only one service process/worker, with auto-reload disabled; the evaluation CLI in M3 acts only as an HTTP client.

`QAService.ask_with_trace` adds internal-only ask_id/on_progress parameters; the original public ask signature remains compatible. trace adds sources_verified, actual config, and fingerprint, so the model/prompt at the time can be reviewed even on failure. SQLite marks failed evidence that did not pass source verification as unverified, and does not use it as a normal cited answer.
