**C任务：评估、人工评分与恢复说明**

更新日期：2026-11-19。M3软件功能已实现；正式题集和法规尚未接入。本文的正式实验操作要等A交付后执行，现在不要为跑通命令自行补写标准答案。

**这一部分在做什么。**

A先出好30道题，并写好参考答案、关键事实及原文证据。程序让系统在f400、s400、f800、s800四种分块条件下各答一遍，共保存120条记录。四组使用相同题目、语料、索引版本和生成参数。标准答案只留给评估和评分，不发给模型。

你的评分工作是阅读系统已经生成的答案，对照A的标准答案和本轮原文证据作判断。你不需要代A出题，也不能修改标准答案来迁就系统输出。

每个run_id表示一次实验，每个task_id表示后台任务；同一道题在不同条件下各有一条记录、独立问答编号和评分。任务completed只表示120项已处理完，仍要查看errors；失败题也保留。

**正式运行前需要具备的东西。**

- A的data/manifest.json、冻结原文、处理后文档，以及data/eval/gold.jsonl和题集manifest。题集为24道可答题、6道应拒答题，版本必须匹配。
- B的真实embedding依赖、模型和四组完成的索引。
- config/experiment.json的实际版本与参数；正式模式使用真实SHA-256版本，不使用fixture命名。
- 可用的生成服务配置。密钥通过本地env传入，不放进仓库、实验导出或模型消息。

这些前置条件目前尚未全部具备。默认配置的gold_version仍为null；程序会拒绝正式实验，不会自动换成演示题。

**服务与命令行怎样配合。**

以下命令均在DERag目录执行。先在一个终端启动唯一服务，保持其运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

只启动一个worker，不加reload。默认读取项目.env；也可在启动前设置DERAG_ENV_FILE为已有本地env的路径。学校API私密配置位置见工作区外层《学校LLM_API对接文档.md》。

正式前置条件具备后，在另一个终端提交：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_eval --config config/experiment.json --base-url http://127.0.0.1:8765
```

CLI先核对本地与服务实际配置，随后只通过HTTP提交、轮询、导出，不另起工作器或接管数据库。默认导出到data/runs/client-随机编号/；可用--output-dir选择尚不存在的目录。JSON保留完整记录，CSV每行是一个条件的一道题，包括失败项。

终端先显示run_id/task_id，请保留它们。默认等待上限7200秒，可用--timeout调整。轮询超时不会取消后台实验，不要因为没等到就再次提交。

重新打开终端后，用原编号读取，不重新生成：

```powershell
.\.venv\Scripts\python.exe -m scripts.run_eval --config config/experiment.json --base-url http://127.0.0.1:8765 --run-id 原来的run_id
```

读取已有结果允许生成服务当前未就绪，但本地与保存配置仍须匹配。后台任务失败时也导出已保存记录，CLI用非零状态退出。

**怎样评分。**

M3已经提供评分API，页面评分表单在M4接入。服务运行后打开http://127.0.0.1:8765/docs查看接口。先GET /api/evaluations找实验，再GET /api/evaluations/{run_id}查看逐题结果、标准证据、本轮引用和待评分数量。

PATCH /api/evaluations/{run_id}/cases/{case_id}?condition=s400只修改该条件该题：

```json
{
  "answer_grade": "correct",
  "claim_reviews": [
    {"claim_index": 0, "supported": true, "reason": "写明引用原文如何支持这条主张"}
  ],
  "refusal_correct": null,
  "reviewer": "填写实际评审人",
  "notes": "写明核对了哪些必要事实，以及缺失或错误"
}
```

这只是字段示例，不是预先给正式题打分。claim_index从0开始，指本条答案的claims位置；引用编号n从1开始，绑定本轮ask_id。评审时间自动记录，修改留历史。PATCH只更新提交的字段；显式null可撤回待核验。

| 评审对象 | 怎么判断 |
| --- | --- |
| 可答题答案 | correct：必要事实正确且完整；partial：只答对一部分；wrong：错误或误拒答。只有correct计入答案正确率。 |
| 每条事实主张 | 阅读该主张实际引用的本轮证据，判断能否支持结论，并写reason。不能只看编号存在就打true。 |
| 应拒答题 | answer_grade为null，填写refusal_correct；生成了答案不能标正确拒答。若出现事实主张，仍核验引用。 |
| 技术失败 | 保留error，不伪造生成答案，不作为可人工打分的完成答案。 |

自动指标不能通过评分接口覆盖；无效条件、越界主张、与题型矛盾的评分会被拒绝。

**怎样读指标。**

- hit@1/hit@5：同一文档内前k个块的区间并集必须完整覆盖标准证据；半句话不算。多证据分别报告any和all，跨文档不合并位置。分母固定24。
- 答案正确率=correct/24；拒答正确率=正确拒答/6。失败不删题，partial、wrong、误拒答和errors单列。
- 引用正确率=人工确认被所引证据支持的主张数/带引用的事实主张数。未核验时pending不为0，value为null；无引用分母也为null。失败题数另列，不假设失败请求里有多少有效主张。
- 每个比例保存numerator、denominator、pending和failed_cases。hit可能在后续生成失败时仍已命中，不能直接从命中分母减去失败数。
- 耗时中位数只汇总成功结果；上下文字符数和可取得的token数另存。token区分已知/未知尝试，包含修复重试；未知不会冒充0费用。
- review_complete表示没有待评分项；finalizable还要求运行完成、没有模型漂移。仍须看errors。synthetic测试结果的formal_results始终为false。
- paired_cases把同一case_id的四组结果放在一起，方便分析哪种分块更好、为什么失败。

**导出和关机。**

GET /api/evaluations/{run_id}/export?format=json或format=csv只读取保存结果，不重新检索或调用模型。CSV对可能被表格软件当公式的独立文本加前缀；精确原文仍在嵌套JSON和JSON导出中。

每题先登记、检索后保存证据、每次生成尝试保存进度。硬关机后，下次服务启动把未完成题和任务标为PROCESS_INTERRUPTED，已完成答案和评分保留，不自动重试收费请求。需要重跑时创建新实验，保留旧run_id作为失败记录。正常退出会等自己的工作器完成；正式实验尽量保持电脑运行，完成并导出后再关机。
