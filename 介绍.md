# DERag Project Introduction (for team members)

## What this is

DERag is the regulatory question-answering project for CS5481 Data Engineering topic 5. The project plans to collect verifiable official source texts, compare two chunking methods—"Fixed window" and "Article structure"—and make citations in answers traceable back to the source text and specific locations. For detailed experiment specifications, see [项目设计.md](./项目设计.md).

**What is currently delivered is a frontend preview, not a completed RAG system.** The Q&A content, citations, and evaluation numbers are all clearly marked interface samples and cannot be used as course experiment results.

## Getting it running

Docker Desktop is recommended. Team members need to obtain this project's `DE.tar`; if they also need to develop, they need the entire `DERag` source directory as well. The Docker image tag is lowercase `de:latest`, and the container name is uppercase `DE`.

1. Open Docker Desktop and wait for the Docker Engine to start.
2. Open PowerShell in the `DERag` directory and, on first run, execute:

   ```powershell
   docker load -i .\DE.tar
   docker run -d --name DE -p 127.0.0.1:8766:8000 de:latest
   ```

3. Open http://127.0.0.1:8766 in a browser. To check service status, run:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8766/api/health
   ```

   A normal response contains `"status":"ok"`.

Once the container has been created, there is no need to run `docker load` or `docker run` again. On the **Containers** page in Docker Desktop, find `DE` and click **Start**; you can also run `docker start DE`. To stop, click **Stop** on the page, or run `docker stop DE`. If it says the container name `DE` already exists, first check the Containers page and simply start the existing container.

Without Docker, you can follow [README.md](./README.md) to create the project's own `.venv` with Python 3.13, then install dependencies from the locked-version `requirements.txt`; the developer computer's Python path is not needed.

## What you can view now

| Page | Currently available actions |
| --- | --- |
| Chat | Create and switch sessions, send questions, and click source numbers in the demo answer to view evidence snippets. |
| Documents | Browse sample documents, import `.md` / `.txt` in the current browser, and view text and chunk previews. |
| Chunk comparison | Select a document and the F400, S400, F800, S800 conditions to view chunk boundaries, chunk counts, and lengths. |
| Evaluation | View and export per-question reports marked as demo data. |

Chat sessions and locally imported files are stored only in each browser's local storage; they are not synced to other team members and are not written into the Docker image.

## What still needs to be done

- Verify and freeze the official regulatory sources, original snapshots, cleaned text, and character positions in the source text.
- Implement the two chunking methods in the backend and the four conditions of 400/800 characters, using the same corpus and embeddings to build a rebuildable vector index.
- Integrate real retrieval and model-based question answering; the citations for every factual conclusion must point to the evidence from this round and the original text snapshot.
- Freeze the question set, complete the four comparison groups, re-verification, and human scoring, and export the real per-question records and metrics.

After these features are integrated, `requirements.txt`, the Docker image, `DE.tar`, and the run instructions need to be updated. `DE.tar` is large and has been excluded from Git commits; it needs to be transferred separately when delivering to team members.
